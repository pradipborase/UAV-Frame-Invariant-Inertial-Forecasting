# Post-hoc reporting correction (source-selected B3 Ridge)

This document records a **reporting correction** in the public reproducibility package. It is not a retraining, retuning, or target-domain model-selection step.

## What changed

The original Stage-2/Stage-3 audit artifacts retained a descriptive best-frozen-Ridge comparison in which B2 happened to give lower UZH->EuRoC target error. During manuscript audit, this was identified as inconsistent with the study's source-only selection principle. The final manuscript therefore uses B3, selected exclusively from UZH source validation, as the primary Ridge comparator. No model was retrained, no hyperparameter was retuned, and no target-domain data were used to make a new fitted model. The original frozen artifacts are retained for audit transparency.

## Locked source-only Ridge freeze (unchanged)

From `results/stage2/SOURCE_MODELS_FROZEN.md`, written before transfer evaluation:

- EuRoC source: **B3_RIDGE_QF_QW** (lag 25, alpha 0.0001)
- UZH-FPV source: **B3_RIDGE_QF_QW** (lag 10, alpha 0.01)

Those identifiers were chosen with source-domain validation only. The correction is to **use those same frozen objects as the primary comparator in both zero-shot directions**.

## Primary comparator map used by the manuscript

| Context | Primary Ridge | Rule |
| --- | --- | --- |
| WITHIN_EUROC | B3_RIDGE_QF_QW | source-only nested LORO |
| WITHIN_UZH | B3_RIDGE_QF_QW | source-only nested LORO |
| EUROC_TO_UZH | B3_RIDGE_QF_QW | frozen EuRoC source B3, zero-shot |
| UZH_TO_EUROC | B3_RIDGE_QF_QW | frozen UZH source B3, zero-shot |

B3 is the primary Ridge comparator in both zero-shot transfer directions because it was selected exclusively by source-domain validation. B2 is retained only as a supplementary sensitivity baseline.

## Where to find which files

- **Manuscript-facing outputs:** `publication_current/` (regenerated by `scripts/build_publication_current.py` from frozen Stage-2/3 CSVs; no training).
- **Frozen modelling results (do not rewrite):** `results/stage2/` and `results/stage3/`.

`scripts/build_publication_current.py` hardcodes `B3_RIDGE_QF_QW` for all four contexts. It never chooses Ridge by inspecting target-domain RMSE.

## Public-release path redaction (non-scientific)

Stage-0C and Stage-1 audit CSVs/JSON originally stored absolute Windows paths to the study machine. In this public package those path *strings* were rewritten to repository-relative paths so the release does not depend on local user-profile paths. Numeric hashes, counts, and scientific fields were not changed. **Stage-2 and Stage-3 frozen result CSVs were not modified.**

## What was not done

- No Stage 1, Stage 2, or Stage 3 modelling was rerun.
- No checkpoint was loaded or updated.
- No Zenodo DOI was minted in this package.
- `GITHUB_RELEASE_V1` and `GITHUB_RELEASE_V2` were left unmodified.
